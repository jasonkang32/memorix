# Memorix Google Play Data Safety Draft

App package: `com.mebonsoft.memorix`  
Version observed: `0.1.4` / versionCode `5`  
Draft date: 2026-07-20

> This is a draft checklist for Google Play Console Data Safety. Confirm final answers after Billing integration and final dependency audit.

## High-Level Position

- Ads: No
- Account creation: No
- Server-side user content storage: No, planned local-first
- User content processed primarily on device
- In-app purchase: Yes, planned one-time Pro product
- Data deletion: User can delete records/reset app data locally

## Data Types — Likely Google Play Answers

### Photos and videos

Collected/processed by app: Yes, if user selects/imports them.  
Shared externally by app: No, unless user explicitly shares/backs up outside the app.  
Purpose: App functionality.  
Required/optional: Required only for photo/video import features.  
Stored: On device/local app storage.

### Files and docs

Collected/processed by app: Yes, if user selects/imports documents.  
Shared externally by app: No, unless user explicitly shares/backs up outside the app.  
Purpose: App functionality.  
Stored: On device/local app storage.

### User-generated text/content

Examples:

- notes
- tags
- OCR text
- location/country/region labels typed by user

Collected/processed by app: Yes, locally.  
Shared externally by app: No by default.  
Purpose: App functionality/search/organization.

### App activity

Examples:

- hidden/favorite/archive flags
- app settings
- language setting
- backup/restore state
- Pro entitlement cache

Collected/processed by app: Yes, locally.  
Shared externally by app: Purchase entitlement may be verified via Google Play Billing after implementation.  
Purpose: App functionality, fraud prevention/payment entitlement.

### Financial info / purchase history

Handled by: Google Play Billing.  
App receives purchase token/product entitlement state; it should not collect payment card details.  
Purpose: In-app purchase/Pro entitlement.

### Device or other IDs

Current app does not intentionally collect advertising ID or analytics identifiers.  
Confirm after Billing SDK integration.

## Security Practices

- Data encrypted in transit: Not generally applicable for local content; Google Play Billing uses Google infrastructure.
- User can request/delete data: Local records can be deleted/reset in app; uninstall removes app data depending on Android backup behavior.
- Data shared with third parties: No ads/analytics planned. Google Play Billing used for purchases.
- Independent security review: No, unless JK chooses to obtain one.

## Google Play Data Safety Draft Answers

### Does your app collect or share any required user data types?

Suggested answer:

```text
Yes, the app processes user-selected photos/videos/files and user-entered notes/tags for app functionality. The data is stored locally on the user's device and is not shared with the developer's server by default.
```

### Is all user data collected by your app encrypted in transit?

Suggested answer:

```text
Not applicable for locally stored user content. Network communication related to Google Play Billing is handled by Google Play services.
```

If Google Play requires binary Yes/No, answer after final SDK audit.

### Can users request that data be deleted?

Suggested answer:

```text
Yes. Users can delete individual records, delete tags, reset all app data, or uninstall the app to remove local data.
```

### Does your app share data with third parties?

Suggested answer:

```text
No user content is shared by default. Google Play Billing processes purchases when the user chooses to buy Pro.
```
